# agent-ops · 给多个 AI 搭班子用的「工程纪律层」

> 别人做 agent 框架，做记忆检索；这个仓库只做一件事：
> **让一群只会干活、不会记事的 AI，可交接、可重放、可追责。**

```
事件流(真相) ──推导──> 视图(任务板 / 队列 / 摘要)
      ▲                     │
      │ 追加写               │ 判据体检（每条检查必须登记"怎么让它变红"）
      │                     ▼
多机桥(文件协议) ──> 会话(场景卡/pin) ──> 调度(派单闸) ──> 插件(每轮注入)
```

三条铁律：

1. **状态只有一个真源**（事件流），其余全是视图，随时可重建；
2. **跨机只走文件契约**，不共享内存、不共享上下文；
3. **判据必须带反证**：说不清"怎么让它变红"，绿的也不算数。

## 这个仓库里有什么（以及没有什么）

| 有 | 没有 |
|---|---|
| 事件流内核（append-only + 投影 + 幂等 + 租约 + 死信） | 不做向量检索、不接模型 |
| 入库闸门（校验→重复→冲突→用途→等级）→ 见 [memory-ingest-gate](https://github.com/XY-livo/memory-ingest-gate) | 不含任何真实记忆内容 |
| 桥协议（inbox→working→done + 回执 + 分片游标） | 不做 RPC 框架 |
| 交接与换会话（2 小时内没写交接，拒绝换人） | 不绑定任何 agent 框架 |
| 判据体检（16 条 + 反证登记） | 不代替你判断业务对错 |

一句话：**它是骨架，不是产品。**

## 60 秒

```bash
git clone https://github.com/XY-livo/agent-ops && cd agent-ops
python3 src/events.py selftest      # 不碰你的数据
bash demo/run.sh                    # 从零到一张可重建的任务板
```

demo 会演示四件事：

```
① 建任务            → 写入一行事件
② 认领（租约+栅栏）  → 谁在干、什么时候到期
③ 完成记两次        → 第二次被拒（同一件事不许记两次）
④ 视图              → 板子由事件推出来，不是人工维护的
```

**最值得试的一步**：把 `_events.local.jsonl` 最后一行删掉，再跑 `board`——板子会退回「进行中」。
因为板子从来不是真相，它只是投影。

## 为什么是 append-only

| 常见做法 | 问题 |
|---|---|
| 直接改状态文件 | 改坏了没法回滚；"谁改的、为什么"永远查不到 |
| 数据库里覆盖式更新 | 同上，且历史要另开一张表 |
| **只追加事件，视图算出来** | 任何时刻可重放；视图错了重建就行；审计天然存在 |

代价是：**你要接受"状态是算出来的"**。这需要一点纪律，但换来的是——你永远能回答"事情是怎么变成现在这样的"。

## 核心概念（六个，够用）

| 概念 | 一句话 |
|---|---|
| **cor** | 一条链的 id（一个任务、一件事） |
| **append-only** | 事件落盘后永不修改；要改就再发一条 |
| **投影（projection）** | 板子/队列/摘要都是算出来的视图 |
| **幂等键（biz_key）** | 同一件事重复提交会被拒，不会记两次 |
| **租约 + 栅栏（lease/fence）** | 谁在干、到期时间、换人时如何不打架 |
| **死信（dead letter）** | 被拒的事件留在文件里，可查、可重放 |

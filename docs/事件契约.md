# 事件契约 v0.1

> 一份契约解决三件事：**字段长什么样、什么算合法、什么算同一件事**。

## 一、信封（每条事件都有）

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 全局唯一。重复 id 直接拒 |
| `at` | ✅ | 带时区的时间戳：`2026-11-06T10:00:00+08:00`。**裸时间不算数** |
| `cor` | ✅ | 链 id：一个任务/一件事 |
| `kind` | ✅ | 事件类型（见下表） |
| `source` | ✅ | 谁干的（角色/场景名，不是机器名） |
| `ver` | ✅ | 契约版本，当前 1 |
| `payload` | ✅ | 该类型要求的字段 |

**为什么 `at` 必须带时区**：两台机器、两种时钟，不带时区的时间没法排序，也没法判断谁先。

## 二、事件类型与 payload 必填项

| kind | payload 必填 | 语义 |
|---|---|---|
| `task.created` | `title` | 建一条任务 |
| `task.claimed` | `by`, `lease_until`, `fence` | 认领（带租约与栅栏） |
| `task.completed` | `by`, `evidence` | 完成。**没有证据不算完成** |
| `task.blocked` | `why` | 挂起 |
| `task.dropped` | `why` | 丢弃 |
| `lease.renewed` | `lease_until`, `fence` | 续租 |
| `note` | — | 备注 |
| `check.passed` / `check.failed` | `checker` | 体检结果 |

## 三、什么算「同一件事」（幂等键）

| kind | biz_key |
|---|---|
| `task.created` | `created\|cor\|title` |
| `task.claimed` | `claimed\|cor\|fence=n` |
| `task.completed` | `completed\|cor` |
| `task.blocked` / `dropped` | `kind\|cor` |

**为什么要按 kind 分前缀**：如果所有类型共用 `cor` 作键，那么「认领」和「完成」会被判成同一件事，第二条直接被拒——动作全丢。

## 四、租约与栅栏

`task.claimed` 必须带 `lease_until` 和 `fence`：

- **租约**：到期没续 = 这个人可能挂了，任务可被回收
- **栅栏**：每次换人 fence+1；旧持有者的后续事件因为 fence 旧，会被认出来并拒绝

**为什么需要栅栏**：没有它，两个执行者同时干同一件事，最后写的事件谁后到谁算数——而「后到」和「对」没有任何关系。

## 五、不变量（写进代码，不靠记性）

1. 事件不可修改：要改就再发一条
2. 同一 biz_key 只能出现一次
3. 视图任何时候可重建，且结果一致
4. 被拒的事件不丢：记下来，可查

## 六、边界

- 分片（local/cloud）按写入方分开，合并时**按分片顺序 + 行号**，不按 `at` 排序
- 时间只用于展示与租约判断，不用于排序
